# 2FA

Локальный TOTP-аутентификатор для терминала. Хранит Base32-секреты по именам
аккаунтов в зашифрованном файле и генерирует шестизначные коды по RFC 6238
(HMAC-SHA1, шаг 30 секунд).

## Возможности

- аккаунты с именами, описаниями и датой создания;
- генерация кода по имени аккаунта или по сырому Base32-секрету;
- скрытый ввод секретов и паролей;
- шифрование AES-256-GCM;
- ключ в системном keyring или пароль через Argon2id;
- команды `add`, `list`, `edit`, `rename`, `remove`, `rekey`, `init`, `docs`;
- короткие псевдонимы команд;
- подробная документация в форматах text, markdown и man;
- отсутствие сетевых запросов и телеметрии.

## Сборка

Требуется Go 1.26 или новее.

```bash
./build.sh
```

Скрипт собирает `2fa` без отладочных символов (`-s -w`), с `-trimpath` и без build ID, по умолчанию без cgo (`CGO_ENABLED=0`). Версия берётся из `git describe` и встраивается в бинарник.

Примеры:

```bash
./build.sh -o dist/2fa
VERSION=1.0.0 ./build.sh
./build.sh --version 1.0.0
GOOS=linux GOARCH=arm64 ./build.sh -o dist/2fa-linux-arm64
```

Если git недоступен, версия будет `dev`; её можно задать через `VERSION` или `--version`.

Проверка:

```bash
go test ./...
```

## GUI (Wails)

GUI использует Wails v3 и находится в отдельном модуле `gui/`. Он не компилируется в составе `go test ./...` и не требует Node.js: фронтенд — статические HTML/CSS/JS.

Требования:

- macOS: Xcode Command Line Tools;
- Linux: GTK4 + WebKitGTK 6.0, `pkg-config`, gcc;
- Windows: WebView2.

Сборка:

```bash
./build-gui.sh
```

Скрипт собирает release-бинарник в `gui/build/bin/2fa` без отладочных символов, с `-tags production`, `-trimpath` и версией из `git describe`. Для Windows добавляется `-H windowsgui`.

Примеры:

```bash
VERSION=1.0.0 ./build-gui.sh
GOOS=darwin GOARCH=arm64 ./build-gui.sh -o gui/build/bin/2fa-darwin-arm64
```

Скрипт собирает Go-бинарник. Для полноценной упаковки в `.app`/установщик нужен Wails CLI и отдельная настройка упаковки под целевую ОС; в этом репозитории она не настроена.

Возможности GUI:

- menubar/tray-приложение без иконки в Dock на macOS;
- избранные аккаунты в меню трея, копирование кода по клику;
- главное окно со списком аккаунтов, поиском, избранным и описаниями;
- глобальный 30-секундный индикатор смены кода;
- добавление, редактирование, удаление и переименование аккаунтов;
- смена провайдера ключа (`rekey`);
- шифрованный экспорт/импорт `.2fa`;
- блокировка/разблокировка vault.

По умолчанию GUI создаёт vault с ключом в системном keyring; если keyring недоступен, предлагается пароль. Экспорт всегда шифруется паролем. Коды не отображаются, а копируются по кнопке.

## Быстрый старт

```bash
# Создать хранилище (по умолчанию выберется keyring или пароль)
./2fa init

# Добавить аккаунт; секрет можно передать аргументом или ввести скрыто
./2fa add github JBSWY3DPEHPK3PXP --desc "GitHub"

# Получить код
./2fa github
./2fa code github

# Список аккаунтов, в том числе с описаниями
./2fa list
./2fa list --ext
```

Если `add` вызван без секрета, программа запросит его скрыто. При вводе с
терминала секрет запрашивается дважды; при чтении из pipe — одной строкой без
подтверждения.

## Команды

| Команда | Псевдонимы | Назначение |
|---|---|---|
| `2fa <аккаунт\|секрет>` | — | получить код; сначала ищется аккаунт, затем сырой Base32-секрет |
| `2fa code <аккаунт\|секрет>` | `c`, `g` | получить код; сырой секрет только с `--raw` |
| `2fa list [--ext]` | `ls`, `l` | список аккаунтов; `--ext`/`-e` добавляет описания |
| `2fa add <имя> [секрет]` | `a` | добавить аккаунт; флаги `--desc/-d`, `--force/-f` |
| `2fa remove <имя>` | `rm`, `del` | удалить аккаунт |
| `2fa edit <имя>` | `e` | изменить `--desc/-d` и/или `--secret/-s` |
| `2fa rename <старое> <новое>` | `mv` | переименовать аккаунт |
| `2fa rekey --to <провайдер>` | `rk` | перешифровать хранилище под другой провайдер |
| `2fa init` | `i` | создать пустое хранилище (идемпотентно) |
| `2fa docs [-f text\|markdown\|md\|man] [-o PATH]` | `doc`, `manual` | подробная документация |

Глобальные флаги:

| Флаг | Назначение |
|---|---|
| `--config`, `-c` | путь к файлу хранилища (env `2FA_CONFIG`) |
| `--key-provider`, `-k` | `auto`, `keyring`, `passphrase` или `plaintext` |
| `--raw`, `-r` | считать аргумент сырым Base32-секретом |
| `--secret-stdin` | читать секрет из stdin |
| `--passphrase-stdin` | читать пароль из stdin |

Если одновременно используются `--secret-stdin` и `--passphrase-stdin`, строки
читаются по порядку: сначала секрет, затем пароль vault.

## Как выбирается аккаунт

Для `2fa <аргумент>`:

1. `--raw` всегда трактует аргумент как Base32-секрет.
2. Если хранилище открылось и есть аккаунт с точным именем, используется он.
3. Иначе корректный Base32-аргумент используется как сырой секрет.
4. Если хранилища нет, корректный Base32-аргумент тоже используется как сырой.
5. Если хранилище не открылось (например, недоступен keyring), корректный
   Base32-аргумент используется как сырой с предупреждением в stderr.

Команда `code` не использует сырой секрет без `--raw`. Для явного сырого
секрета:

```bash
./2fa code --raw JBSWY3DPEHPK3PXP
```

Имена аккаунтов чувствительны к регистру. Пробелы и управляющие символы
запрещены; имя не может начинаться с `-`.

## Хранилище и шифрование

По умолчанию файл находится в `os.UserConfigDir()/2fa/accounts.json`
(обычно `~/.config/2fa/accounts.json`). Путь можно изменить флагом `--config`
или переменной `2FA_CONFIG`.

Поддерживаются провайдеры ключа:

- `keyring` — случайный 32-байтовый ключ в системном хранилище секретов
  (Secret Service в Linux, Keychain в macOS, Windows Credential Manager);
- `passphrase` — ключ выводится из пароля через Argon2id (3 итерации,
  64 МиБ, 4 потока, соль 16 байт);
- `plaintext` — без шифрования, только для отладки; программа предупреждает.

При `--key-provider auto` новое хранилище сначала проверяет keyring и при
недоступности выбирает `passphrase`. Существующее хранилище всегда открывается
своим провайдером. Сменить провайдер можно командой `rekey`:

```bash
./2fa rekey --to passphrase
./2fa rekey --to keyring
```

Для режима `keyring` одного файла `accounts.json` недостаточно для переноса на
другую машину: ключ хранится в системном keyring. Перед переносом выполните
`rekey --to passphrase` (или переносите ключ отдельно).

Файл создаётся с правами `0600`, каталог — `0700`. Запись выполняется атомарно
через временный файл и `rename`. Полезная нагрузка шифруется AES-256-GCM;
заголовок с версией, `vault_id`, провайдером, шифром и параметрами KDF
аутентифицируется как additional authenticated data.

## Безопасность

- Секреты и пароли не логируются.
- Ввод с терминала скрыт; при вводе из pipe подтверждение не запрашивается.
- Секрет в аргументе (`add <имя> <секрет>`, `edit --secret`) попадает в историю
  оболочки и может быть виден через `ps`. Предпочитайте скрытый ввод,
  `--secret-stdin` или pipe.
- `2FA_PASSPHRASE` удобна для скриптов, но может быть видна другим процессам
  пользователя.
- Защита не работает против вредоносного ПО, работающего от вашего
  пользователя, дампов памяти или подмены бинарника.

## Документация

Встроенная подробная документация:

```bash
./2fa docs                    # текст в stdout
./2fa docs -f markdown        # markdown
./2fa docs -f man             # man-страница
./2fa docs -f markdown -o docs/2fa.md
```

`docs` не открывает хранилище и не требует пароля.

## Алгоритм

Реализован [RFC 6238](https://tools.ietf.org/html/rfc6238) (TOTP):

1. Base32-секрет декодируется в байты.
2. Unix-время делится на шаг 30 секунд.
3. Номер шага переводится в 8-байтное Big Endian представление.
4. Вычисляется HMAC-SHA1 от времени с ключом.
5. Динамическое усечение извлекает 4 байта.
6. Результат приводится к 6 цифрам с ведущими нулями.

Алгоритм совместим с Google Authenticator, Authy, Microsoft Authenticator и
другими стандартными TOTP-приложениями.
