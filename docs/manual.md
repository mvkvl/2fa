## Назначение

`2fa` — небольшой локальный TOTP-аутентификатор для терминала. Он хранит
Base32-секреты по именам аккаунтов и генерирует шестизначные коды по алгоритму
RFC 6238 (HMAC-SHA1, шаг 30 секунд, 6 цифр).

Версия: `{{VERSION}}`.

Программа не обращается к сети, не содержит телеметрии и не отправляет секреты
во внешние сервисы. Все данные остаются в локальном файле, путь к которому можно
изменить флагом `--config`.

## Быстрый старт

```console
$ 2fa init
$ 2fa add github JBSWY3DPEHPK3PXP --desc "GitHub"
$ 2fa code github
123456
$ 2fa list --ext
NAME    DESCRIPTION
github  GitHub
```

Если при `add` не указать секрет, программа запросит его скрыто. При вводе с
терминала новый секрет или пароль запрашивается дважды для защиты от опечатки.
При чтении из pipe подтверждение не запрашивается.

Самый короткий вариант получения кода:

```console
$ 2fa github
123456
```

## Аккаунты и разрешение аргументов

Имена аккаунтов чувствительны к регистру. Допускаются любые символы, кроме
пробельных и управляющих; имя не может быть пустым, начинаться с `-` или быть
длиннее 128 символов. Имена команд и их псевдонимов не запрещены, но при
неоднозначности команда имеет приоритет.

Корневая команда `2fa <аргумент>` разрешает аргумент так:

1. Если указан `--raw`, аргумент всегда считается Base32-секретом, а хранилище
   не открывается.
2. Если хранилище открылось и в нём есть аккаунт с точным именем, используется
   его секрет.
3. Если точного имени нет, но аргумент является корректным Base32-секретом,
   он используется как сырой секрет.
4. Если хранилище отсутствует, корректный Base32-аргумент используется как
   сырой секрет; иначе выводится подсказка выполнить `2fa init`.
5. Если хранилище существует, но не открылось (например, недоступен keyring или
   отменён ввод пароля), корректный Base32-аргумент всё равно используется как
   сырой секрет с предупреждением в stderr. В остальных случаях возвращается
   ошибка открытия.

Команда `2fa code <аргумент>` всегда сначала ищет аккаунт по точному имени и
не использует сырой секрет без явного `--raw`. Для сырого секрета используйте
`2fa code --raw <секрет>`.

## Команды

`init` создаёт пустое хранилище. Повторный вызов идемпотентен: программа
открывает существующее хранилище и печатает путь, провайдер и число аккаунтов.
Если явно указан другой провайдер, возвращается ошибка с подсказкой `rekey`.
Повреждённый файл никогда не перезаписывается.

`add <имя> [секрет]` добавляет аккаунт. Если секрет не передан, он запрашивается
скрыто (или читается одной строкой из stdin). Флаг `--desc`/`-d` задаёт
описание. Существующий аккаунт можно перезаписать только с `--force`/`-f`;
при этом сохраняются `created_at` и, если `--desc` не указан, старое описание.

`list` печатает имена аккаунтов по одному в строке в лексикографическом порядке.
`list --ext`/`-e` добавляет колонку с описанием. Если хранилище не создано или
пусто, выводится подсказка в stderr и код возврата 0.

`edit <имя>` изменяет описание и/или секрет. Можно использовать `--desc`/`-d`,
`--secret`/`-s` или глобальный `--secret-stdin`. Нужен хотя бы один параметр.
Пустое значение `--desc ""` очищает описание.

Если одновременно используются `--secret-stdin` и `--passphrase-stdin`, строки
читаются по порядку: сначала секрет, затем пароль vault.

`rename <старое> <новое>` переименовывает аккаунт, сохраняя секрет, описание и
дату создания. Если новое имя занято, возвращается ошибка.

`remove <имя>` удаляет аккаунт без дополнительного подтверждения.

`rekey --to keyring|passphrase|plaintext` перешифровывает существующее
хранилище под другой провайдер, сохраняя `vault_id` и все аккаунты. Старый ключ
keyring удаляется по возможности; если удалить его не удалось, выводится
предупреждение.

`docs` выводит подробную документацию в формате `text`, `markdown` (псевдоним
`md`) или `man`. По умолчанию используется `text` и stdout. Флаг `--output`/`-o`
записывает документацию в файл; `-o -` означает stdout.

## Режимы хранения

Поддерживаются три провайдера ключа:

- `keyring` — случайный 32-байтовый ключ хранится в системном хранилище
  секретов (Secret Service в Linux, Keychain в macOS, Windows Credential
  Manager). В самом файле хранилища лежит только зашифрованный payload и
  идентификатор `vault_id`. Это рекомендуемый режим по умолчанию, если keyring
  доступен.
- `passphrase` — ключ выводится из пароля через Argon2id (соль 16 байт,
  3 итерации, 64 МиБ памяти, 4 потока, 32-байтовый ключ). Пароль запрашивается
  при каждом открытии хранилища. Для скриптов можно задать `2FA_PASSPHRASE`.
- `plaintext` — без шифрования. Явный режим для отладки или недоверенной среды;
  программа предупреждает об этом. Не используйте его для реальных секретов.

При `--key-provider auto` (по умолчанию) новое хранилище сначала проверяет
доступность keyring и выбирает `keyring`, иначе `passphrase`. Существующее
хранилище всегда открывается тем провайдером, который записан в его заголовке.
Если явно указан недоступный `keyring`, программа возвращает ошибку и не
переключается молча на другой режим. Если явно указан провайдер, отличный от
заголовка, возвращается ошибка с подсказкой `2fa rekey`.

Файл хранилища имеет вид JSON с версией формата, `vault_id`, провайдером,
шифром, nonce, параметрами KDF и ciphertext. Шифрование — AES-256-GCM;
заголовок с версией, `vault_id`, провайдером, шифром и KDF используется как
additional authenticated data, поэтому изменение заголовка обнаруживается при
расшифровке. Для `plaintext` применяется `cipher: none`, а payload хранится в
base64.

## Смена режима и резервные копии

Смена режима выполняется командой `rekey`. Например, чтобы перейти с keyring на
пароль:

```console
$ 2fa rekey --to passphrase
Новый пароль vault:
Повторите ввод:
Провайдер изменён на "passphrase".
```

Обратный переход:

```console
$ 2fa rekey --to keyring
```

При резервном копировании файла `accounts.json` помните: для режима `keyring`
сам файл бесполезен без записи в системном keyring. Для переноса на другую
машину используйте `rekey --to passphrase` (или `plaintext`, если понимаете
риски) до копирования, либо отдельно переносите ключ keyring. `vault_id`
специально сохраняется, чтобы файл можно было перемещать между каталогами без
потери связи с ключом.

## Безопасность

- Каталог хранилища создаётся с правами `0700`, файл — `0600`; запись
  выполняется атомарно через временный файл и `rename`.
- Секреты и пароли не выводятся в логи и сообщения об ошибках.
- Ввод секрета и пароля скрыт, если stdin является терминалом. При вводе из
  pipe подтверждение не выполняется.
- Флаг `--secret`/`-s` и позиционный секрет попадают в историю оболочки и могут
  быть видны через `ps`. Предпочитайте скрытый ввод, `--secret-stdin` или
  чтение из pipe.
- Переменная `2FA_PASSPHRASE` удобна для скриптов, но может быть видна другим
  процессам того же пользователя через окружение. Не используйте её на
  многопользовательских машинах без понимания рисков.
- TOTP-секрет — это фактически второй фактор. Защищайте файл хранилища и ключ
  keyring так же, как пароли. Вредоносное ПО, работающее от вашего пользователя,
  может получить доступ к секретам независимо от выбранного режима.
- Программа не защищает от компрометации самой системы, отладчиков, дампов
  памяти или подмены бинарника.

## Переменные окружения

- `2FA_CONFIG` — путь к файлу хранилища. Эквивалент `--config`.
- `2FA_PASSPHRASE` — пароль для режима `passphrase`. Если задан, скрытый запрос
  пароля не выполняется. При создании нового хранилища этот пароль используется
  без подтверждения.

## Файлы

По умолчанию используется `{{CONFIG_PATH}}`.

Каталог можно переопределить флагом `--config` или переменной `2FA_CONFIG`.
Программа не изменяет другие файлы и не создаёт конфигурацию в домашнем
каталоге, кроме этого пути.

## Коды возврата

- `0` — успех, включая `list` при отсутствующем или пустом хранилище.
- `1` — ошибка: неверный секрет, отсутствующий аккаунт, ошибка открытия или
  записи хранилища, недоступный keyring, отменённый ввод и т. п.

## Примеры

Добавить аккаунт со скрытым вводом секрета:

```console
$ 2fa add work --desc "Рабочая почта"
Секрет (Base32):
Повторите ввод:
Аккаунт "work" добавлен.
```

Добавить секрет из pipe:

```console
$ printf '%s\n' "$TOTP_SECRET" | 2fa add work --secret-stdin
```

Получить код по имени и по сырому секрету:

```console
$ 2fa work
$ 2fa --raw JBSWY3DPEHPK3PXP
$ 2fa code work
```

Показать список с описаниями и переименовать аккаунт:

```console
$ 2fa list --ext
$ 2fa rename work job
```

Изменить описание, очистить его и удалить аккаунт:

```console
$ 2fa edit job --desc "Новая почта"
$ 2fa edit job --desc ""
$ 2fa remove job
```

Создать хранилище с паролем и потом перейти на keyring:

```console
$ 2fa init --key-provider passphrase
$ 2fa rekey --to keyring
```

Сохранить markdown-документацию в файл:

```console
$ 2fa docs --format markdown --output docs/2fa.md
```

Показать man-страницу:

```console
$ 2fa docs --format man | man -l -
```
